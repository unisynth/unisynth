# tools

bun/shell build and verification tools. Each `*.test.ts` runs under `bun test`.

| File | Purpose |
|---|---|
| `check-song-features.sh` | Compo-build check of a unified song: `synth-convert features`, then the host `unisynth` render example and the i686 core-only build with exactly those features; `--minimal` drops each listed feature and requires a load failure or different audio. Usage `<song> [--minimal] [bank.dls]`. `--minimal` skips `us-chunk-wide` when `us-strip` is listed (implied). See change: add-v2-import. |
| `check-unisynth-features.sh` | Feature-set gate for `crates/unisynth`: `cargo check` each single-module set (`us-osc-pm` … `us-env-rate`, groups, none, all) for `i686-pc-windows-msvc -Zbuild-std=core` and `wasm32-unknown-unknown`, plus `cargo test` of each set (`--no-test` skips); prints `ok [set]` or the errors; any warning fails. Sets also cover each `us-voice-*`, `us-voice`, and everything but the voice paths (gated instrument tests, loadable goldens). See change: shrink-unified-synth. Also `us-matrix` alone and everything but the matrix. Build-only sets with `us-trusted` (its tests expect validation). Also `us-automation` alone and everything but automation. Also builds `us-osc-combine` and each `us-quirk-*` alone. See change: unify-v2-algorithms 6.5–6.8 (the format switch). |
| `demo-songs/` | Builds the six reference demo songs into `project/music`: `songs.json` (source dirs `WS_SONG_DIR`/`TF_SONGS`, per-song title/author/about, upstream licences and permalinks), `build.ts` (`synth-convert ws\|tfm` → `song import --meta` → `song check`; `meta()` always writes an "adapted version, not the original" description plus the pipeline and its differences; skips songs whose source is absent). `build.test.ts`: manifest and meta rules. Authors a repository does not name say so. `meta/<name>.json` (optional): song `about` + `tracks: [{name, about}]` (blob order, no master) merged by `config()` into the `--meta` import config; `names.ts` (`WAVESABRE=<checkout>`) refreshes WaveSabre track names from `Tests/WaveSabreConvertTests/Refs/<original>.ref` `Tracks[].Name` (master dropped, repeats ` 2`), keeping `about` by index. Descriptions written from an instrument analysis (original WaveSabre device params + note statistics) and web research. See change: add-import-patterns. Seventh song `turtles` (source `enigma-studio-4`, `ES4_SONGS=<Enigma-Studio-4/demos/zoom>`, convert `tf4m`, CC0-1.0). |
| `song-page/` | Listening page for every song in `project/music/**` (demo + released), played live in the browser by the synth (no audio files). `build.ts [out]` (default `song-page/out`, git-ignored): `song export` each → `songs/<slug>.bin` (cache by song sha256, `cache.json`), length from `song check`, `synth.wasm` (`buildSynthWasm(true)`), `songs.json` + static `index.html`; URLs carry `?v=<content hash>` (Pages 10-min cache). Page: render `WORKER` (engine `bounce_open`/`bounce_step` → 1-s int16 chunks, `trunc(fround(x·32767))` = `song render` bytes; demo bit-identical, engage 28 samples ±1 from wasm vs native engine) over a MessageChannel to the `WORKLET` player (plays rendered part, silence + "waiting" past it, seek instant inside it), sticky play/seek bar with rendered fraction, search, credits, `#slug` / `#slug@s`, keys Space ←→ N P. `needsBank(song)` (sampler osc type 1/3, `s7` ≥ 0.5, sample > 0; 17 WaveSabre songs) → only those fetch the GM bank from `BANK_URL` (default `../daw/data/bank.dls`, the bank published with the DAW). `CONTACT`, `ONLY=<regex>`, `JOBS`. Exports `songFiles`, `groupOf`, `slugOf`, `needsBank`, `GROUPS`, `page`. `serve.ts [dir] [port]` (6480): byte ranges, `application/wasm`, `GM_DLS` at `/daw/data/bank.dls`. `build.test.ts`: slugs, groups, bank songs, escaping, synth page. |
| `synth-parity/` | Shared audio parity metrics for synth-mix / engine renders (ws-parity, tf-parity): `metrics.ts` `readWav`/`writeWav` (16-bit / f32), `loudness` (BS.1770-4 integrated LUFS, libebur128 K-weighting at any rate, −70/−10 gates), `octaveLtas` (63 Hz–16 kHz, Hann 8192/4096), `onsets` (log spectral flux, 1024/64, local-mean + 0.1·max peak pick, constant bias cancels), `compare(ours, ref, tol)` → `Report` (`DEFAULT_TOL` 1 dB / 3 dB / 100 frames / 95 % both ways; bands > 60 dB below the loudest skipped), `formatReport`. `cli.ts <ours.wav> <ref.wav> [--onset-frames N] [--json]` exits 1 on FAIL. Tests: 997 Hz −3.01 LUFS, gating, band placement, identical → pass, +3 dB → fail, tilt, onset shift 60 ok / 300 fail. `alignment(ours, ref, maxLag)` (onset-strength cross-correlation: lag, corr), `Tolerance.bandFloorDb`, `Tolerance.onsetAlignment`. |
| `tf-parity/` | Opt-in Tunefish reference parity (tf-song). `build-ref.sh`: clones upstream `paynebc/tunefish` @ 7e48ce8 into `$TF_REF` (default `/tmp/tf-ref`) if absent, builds upstream runtime/synth/player + our MIT `render-ref.cpp` (computes song length itself, skips empty instruments) → `$TF_REF/build/render-ref <song.tfm> <out.wav> [tail]`. `parity.ts`: renders with `cargo --example render` and the reference, `compare` from `synth-parity` with `TOL` (1 dB / 3 dB / onsets 512 frames); songs from `TF_SONGS` or `$TF_REF/media/tf4modules`; no reference → prints skipped, exit 0. Test: tolerance, skip path; full run `TF_PARITY=1`. No GPL code, songs or WAVs committed. |
| `unisynth-parity/` | Opt-in parity, speed and size of the unified synth vs the legacy engines (change add-unified-synth, D11). `parity.ts`: `runItem` (legacy render via `synth-convert` example `legacy`, `synth-convert ws/tfm`, `unisynth` example `render`, `synth-parity` compare), device level (WaveSabre `render_device` songs + Tunefish `PARITY_DUMP` patches) and the six reference songs from `WS_SONG_DIR`/`TF_SONGS` (skipped with a message when absent, exit 0), `RANDOM_DRAWS` judged on `SEEDS` = 8 seeds, speed on `[profile.fast]` plus `release` for the floor songs, `retirement(run)` READY/BLOCKED naming failing items, `formatRun` → `report.md` (metrics only). `signoff.json` records the A/B listening; `size.md` comes from `research/us-size-probe/measure.sh`; `--reuse <dir>` compares cached renders. `parity.test.ts`: verdicts, skip path, report format. `ACCEPTED` lists items judged against a wider tolerance (Global Groove: loudness ±2.5, bands ±4 dB, open filter passed through) and the report section *Accepted differences*. `v2.ts` (+`v2.test.ts`): V2 acceptance songs, v2redux reference vs `synth-convert v2m` → unisynth, song metrics on renders cut to the shorter; writes `v2-report.md` + `v2-signoff.json`; `--renders` → `renders/unisynth/<song>_unisynth.{wav,mp3}`; skips (exit 0) when songs/v2redux absent. See change: add-v2-import. `v2.ts` also runs `AUX_SONGS` (debris_ost, fr-052_platinum, stars; own report section). `cauldron.ts` (change add-cauldron-xm-import): TBL mini-cauldron suite — `SONGS` (jizz, stash_song1, stash_bluish → rebuilt XM + patch JSON), `runSong` (`synth-convert xm` → `render` vs `out/listen/ref44/<song>.wav`, openmpt123 of the bit-exact rebuild), `runPhrase` (`synth-convert xm-phrase <patches> <call> <record> <variant>` vs `ref44/<phrase>.wav`), `judgePhrase` (bands centred above the stored Nyquist not judged), `pingpongSeconds` (converter's `pingpong-seconds` line), `formatRun` → `cauldron-report.md`; `--self` harness check; `CAULDRON_OUT`; material absent → skip, exit 0. `drift.ts` (+ test): `drift(ours, base)` loudness Δ + worst band Δ, `FLAG` 0.5/1.5 dB; `parity.ts`/`v2.ts` `--baseline <dir>` stores renders, `--drift <dir>` compares. `unify-baseline.md`: change unify-v2-algorithms baseline (parity, goldens, bake, size, speed). Cauldron phrases: `leadFrames`/`dropLead` drop `xm-phrase`'s `lead-frames N`; `judgePhrase` judges our mid channel `(L + R)/2` against the mono phrase references (loudness sums channels). See change: add-cauldron-xm-import. `runSong` drops `lead-frames` like phrases (task 6.1). `--onsets` (task 5.2): `clickXm` rewrites every XM sample as a 32-sample click, openmpt123 renders it, `clickTrack` places our `xm-triggers` clicks, `clickStarts` + `onsetMatch` require ≥ `MIN_CLICK_MATCH` 99 % of ours within 100 frames. Cauldron phrases: `judgePhrase` judges only octave bands wholly below the stored Nyquist (`fc·√2 ≤ nyquist`); `phraseRef` → `ref44bw/` (alias-free, from `fullrate_phrases.py`) for decimated phrases, `ref44/` otherwise; skip when `ref44bw/` is absent. See change: add-cauldron-xm-import. `cauldron-signoff.json`: mini-cauldron A/B verdict (approved 2026-10-30), read by `cauldron.ts` into the report. See change: add-cauldron-xm-import. `cauldron.ts` converts songs with `PARITY_OPTIONS` (`--keep-layers --split-pitches --exact-chain`, the layered layout; slim-cauldron-chain). `cauldron-compact.ts` → `cauldron-compact.md`: default (compact) vs layered conversion of the three TBL songs (tracks, bytes, xz, render s, loudness/bands vs reference), audio + `index.html` listening page in `research/tbl-mini-cauldron/out/compact/`. See change: compact-cauldron-xm-import. `drift.ts` also `Profile`/`profile`/`driftOf` (drift from stored profiles). `songs-drift.ts` (unify-v2-algorithms 6.2/6.9): every tracked song, patches as a one-note song, the DAW instrument templates (read from source) → drift profile per item, `--baseline <dir>` / `--against <dir> [--report] [--json]`, `SONG`/`JOBS`/`ONLY`/`GM_DLS`. `quirk-survey.ts --against <songs-base> --out <dir> [--only q]` (6.3): per quirk builds `song` with `us_quirk_off` (target/quirk/<q>), songs-drift over the V2 songs that set it (`versionOf` meta), parity songs vs original; writes `<q>.json`, `quirks.md`; `QUIRKS` = kept candidates. `songs-drift.ts` patch songs are song/2. See change: unify-v2-algorithms 6.5–6.8 (the format switch). `load-all.ts [--externals]` (unify-v2-algorithms 6.9, "No song left behind"): inventory of every held song (tracked, git-ignored when present, lab corpora re-converted with --externals; `ws/unified` rewritten from `refs/`), each `song check`ed (loads in the player, JSON declares `song/2`); fails on a failed/old-format song or fewer than recorded; `UNCONVERTIBLE` lists sources that never converted (reported); writes `load-all.md`. `load-all.test.ts`. |
