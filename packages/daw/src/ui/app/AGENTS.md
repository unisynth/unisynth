# packages/daw/src/ui/app

Session logic (daw-solid-ts 9.1 split of the former `app.js`): live bindings (`session.ts`), edit core with undo (`core.ts`), transport, engine link, arrangement, clips, automation, piano roll, device commands, files, tracks, mixer, tabs, audition. Imperative DOM where a component would cost more (lane SVGs, roll canvas); every song write goes through these modules (`test/write-ratchet.test.ts` counts them).

| File | Purpose |
|---|---|
| `arrange.ts` | Arrangement view (daw-solid-ts 9.1 step 5): live bindings `BW` (+`setBW`), `focusArea` (+`setFocusArea`), elements `ruler`/`hdrs`/`lanes`/`lw`; `initArrange({ rollLoop, rollFollow, rollPos })` builds loop strip, playheads, song-end shade (cursor goes before it: clips.ts) and binds scroll sync, header wheel/focus, ruler loop drag/seek, loop keys, follow hold, zoom wheel/pinch. `rebuildTracks`, `fitSong`, `relayout`, `onLength`, `updateLoop`, `onLoopText`, `toggleLoop`, `loopSelection`, `toggleFollow`, `holdOn`/`holdOnBar`, `showPos` (per frame: follow scroll, playheads by transform), `laneTick`, `zoomArr`, `fitArr`. 9.5: `rebuildTracks(ids?)`: with ids bumps only those tracks (`bumpTracks`) + `applyAutomation`, no relayout/hdrPad. |
| `audition.ts` | Audition (9.1 step 9, never recorded): `noteOn(t, note, vel, key)`/`noteOff(key)`/`allNotesOff` (held by key, roll keys light), `auditionEntry` (library: GSM sample or C3/C1), `toggleKb`, `connectMidi` (notes → armed track, CC1 → MW, bend → PB), `setWheel`/`setBend` (live ctl.wheel/ctl.bend, never in the song). |
| `automation.ts` | Automation (daw-solid-ts 9.1 step 5a): `laneValue`, `applyAutomation` (writes `devst.setAuto` only on change; clears stale), `updateReauto`, record (`recOn`, `setRec`, `recordPoint` touch-overwrite on 1/64 grid, `grab`/`release`/`recordFrame`, push ≤ every 200 ms), `knobEdited`, `curVal`, `laneVals` (mounted lane rows), `addLane` (header + SVG point editor; lazy target select), `addAutoLane`; `initAutomation({ rebuildTracks })`. 9.3: point editor is copy-on-write (`setPt`, filter, spread+sort): `ln.pts` arrays are never changed in place. 9.5: `addLane` draws `laneLine` + handles from `lanePlot` (`HANDLE_PX` 4, window `arrange.laneBars`) in `<g class="hs">`; window change refills the handle group only, queued (`handleQueue`, ≤ 4 ms per frame; a focused lane at once, refocused); `nearPoint` lets a press/right-click take a point without a handle; mount draw skips `applyAutomation` (sets `ovr` itself), `addAutoLane` applies it. |
| `clips.ts` | Clip editing (daw-solid-ts 9.1 step 5b): `initClips(ClipHooks)` binds `#lanes`/`#lanes-wrap`/`#arr-corner` (gestures: title moves, edge resizes, Alt-edge loops, body/empty marquee, own double-click, lane/clip menus); `clipboard` (notes + clips), `instrTracks`, `selClips`, `clearClipSel`, `place` (trims what it covers), `arrCmd` (one undo step), `arrKeys`, `drawCursor`, `createClip`, `makeUnique`, `toggleClipLoop`. Gesture state `ADrag` = edit | marquee union. |
| `core.test.ts` | Unit: session defaults + setters; commit/undo/redo restore values and selection on the demo song, track identity kept, hooks `restored` then `changed`, no-op gesture not a step. |
| `core.ts` | Edit core (daw-solid-ts 9.1 step 2): `initCore({ restored, changed })`, `say(m)` (`#edit-status` + `#live`), `lastSaid()`, `H` (history), `snap()`, `restore(js)` (batch; clears overrides, roll clips by name/start, `restoreSong`, selection), `commit(before, msg)`, `undo()`, `redo()`. DOM optional (no-op outside a page). `announce(m)` / `announced()`: `#live` only (step 5a). Since 9.3: `snap(): Snap` (H = `createHistory<Snap>(snapEqual)`), `commit` drops a `before` from an older `H.epoch`, undo/redo `restore(s, now)` reconciles only differing tracks (`restoreStats.last`), `restoreState` for song loads, primes the lane cache after restore. 9.5: `restored(ids?)`: ids of the tracks a partial restore changed (master id incl.), absent on a full restore. |
| `device.ts` | Device commands (daw-solid-ts 9.1 step 7): `initDevice()` (status line, hidden audio input, `initLive`), `renderDevice` (mounts ui/device/Device.tsx at first call, context line), `renderAll`, `updateWatch` (engine per-voice watch only on Device tab + Live), `senders`, `trackIndex`, `devBypass`, `addEffect`, `useGsm`; internal slot clear/swap (`remapSlots`: mod targets + lanes follow), move/remove effect, GSM import/cleanup, preset save popup. `deviceActions(): DeviceActions` built as `Actions` (mapped type: panel's narrow Track/Device/Param = store track, model Device, engine Param). `loadInto(t, src, it)` (library Load: preset, converted entry + effects, GSM sample, GM instrument; one undo; step 9). Sampler type via `optValue(…, "Sampler")`; a library load that would leave lanes without a parameter is refused (no move to `filt1.cutoff`). See change: unify-v2-algorithms 6.5–6.8 (the format switch). |
| `engine.ts` | Engine link (daw-solid-ts 9.1 steps 3–4): `initEngine({ showPos, seeked, frame })` (wires `E.onStatus`/`E.onError`, remembered buffer + open filters); `songOf(live)`, `audible`, `setSongMeta`, `pushSong` (one at a time, re-runs once if asked meanwhile), `livePush` (30 ms coalesce), `liveLoop`, `unloadLive`, `ensureAudio`, `onBuffer`, `onOpenFilters`, `seek`, `setPlay`, `stopPressed`; per-frame clock `tick`, meters (20 dB/s fall, `PEAK_STEP` publish), load average, audio drops (first 1.5 s ignored). |
| `files.ts` | Song files (daw-solid-ts 9.1 step 8): live `songFile`; `initFiles()` (song list from `DAW.files`, opened file, beforeunload guard), `markClean()` (startup: opened song counts saved), `dirtyUpd` (title, list mark, saved-info; unsaved = other history state id or tempo/sig/length changed), `openSong`/`newSong` (confirm-save first), `save` (local + engine validation, path errors select the track), `importFile`, `exportSong`, `bounceSong`. Opens through `songText`; saves and new songs are `song/2`. See change: unify-v2-algorithms 6.5–6.8 (the format switch). 9.3: `useSong` restores the loaded song's own master via `restoreState` (was reconciled back to the previous song's master). |
| `mixer.ts` | `mixerActions()` (9.1 step 9): strips by id (`trackById` incl. master) → select, mute/solo, volume, inserts (open in Device tab, bypass, add), sends (targets exclude feedback loops; add/remove one undo step; level one undo per gesture). |

| `samples.ts` | Sampler sources (9.1 step 7), reads only: `smpWhat`, `pcmOf` (cached GSM decode), `gsmOf` (library entry → base64), `playSample` (preview AudioContext), `gsmSlot`, `gsmUsed`, `NOBANK`. `gsmOf` reads the song through `songText`.
