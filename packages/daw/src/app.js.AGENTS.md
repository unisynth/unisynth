# packages/daw/src/app.js

Per-file record (sidecar of `packages/daw/AGENTS.md`; pull-only).

UI (`start(DAW)`): arrangement (clips, linked/looping placements, marquee, clipboard, align, overlap trimming, automation lanes from tables), piano roll (notes, velocity lane, quantize, zoom; edge-drag resize of a multi-selection scales every selected length by the grabbed note's factor (grabbed snaps, others to the tick, min 1/4 step), Alt = same amount), transport (engine clock `E.status`, loop strip, follow, meters from engine peaks, load), generated device panels (`pctl`/`pgroup`, fixed slot blocks (`slotBlock`/`slotCard`: every osc/filt/env/lfo slot at its index, unset = collapsed header with type select, ✕ clear in place via `remapSlots(i→0)`, ⇅ swap only between neighbouring filters; mod matrix = `modTable` 12 rows; env/LFO routing hint `routesOf`; collapse: slots `slotOpen` per session, blocks `store` `daw.blk.<k>`; block accent `data-k`; screens `oscView`/`filtView`/`lfoView`/`envView` via `_redraw`; live per-voice overlays: `updateWatch` → `E.watch(selected)` while Device tab shows and `liveOn()` (header button `.livev`, `store` `daw.live`, default on), `liveProbe` parses `status.probe` + 2048-pt FFT of filter taps, `drawLive` per rAF redraws `g.live` only: voice chips `.vox` (16 loudest, "+N"), sampler playheads, env dots by age (`svg._geo`) + level bars, LFO dots, bead stacking, filter in grey/out `--acc` + per-voice cutoff ticks; cost `DAW.debug.live()`) — see change add-device-live-view, effect panels with mode, bypass, reorder, remove), mixer (SolidJS since daw-solid-ts: `ui/mixer.tsx` reads the song store; app.js passes `song` + `MixerActions` to `mountMixer`; no render call needed after an edit; `meters` → `liveState.setPeak`, `show()` → `setMixerShown`, `selectTrack` normalises `selected` to the store proxy + `setSelectedId`; inserts = effect devices, sends, faders, mute/solo → live mute), library (presets via `presetLoad`, GM wave → sampler slot; legacy entries listed only), files (`useSong`, save with local + engine validation and server 422 paths, export blob, import blob, new song, bounce Worker → `wav16`), audition (keyboard on armed track, roll keys, MIDI) → `E.noteOn`. Every commit → `livePush()` (export → `E.update`). `DAW.debug.song()` read-only test hook. Per frame: `showPos` reads scroll before writes, writes changed text only; `applyAutomation` writes knobs only on change; `meters` touch DOM only on visible change (cached by `#mixer` MutationObserver); engine readout = ~0.5 s mean of `load`. `#buffer` select (Low/Normal/Safe/Max, stored `daw.buffer`) restarts audio keeping position and play state. `pushSong` queued (a push during a push runs again after it; never dropped); status `playing:false` stops the UI only for the current `gen`; dead engine → stop, 0% readout, message, Play restarts. Piano roll + controller canvases cover only the visible part (`rollView`, `rollX0` offset, `.roll-size` sizers keep scroll width, redraw on scroll/resize): a 118-bar 950-note clip opens in ~0.3 s. Tracks with automation open their lanes on load (`t.open` default); lanes `role="group"`. Loop off by default; Follow (⇥ Follow) pages at the right edge and a hand-scroll pause resumes when the playhead reaches the edge. Keyboard: tracker layout by `e.code` (`KB_LO` Z–M, `KB_HI` Q–P), octave `[ ]`/PageUp/Down, velocity `; '`, toggle `` ` ``; selecting an instrument track arms it. Automation record (`#rec`, Shift+R, `recordPoint`): 1/64-bar touch writes, lane created + shown, no override, pushes ≤ every 200 ms, held knob writes every frame (`recHold`), one undo per gesture. Sampler slot (`samplerPre`): source select `osc<i>.s7` = choice of 3 (GSM sample 0, GM instrument 0.5, GM wave 1.0), index `osc<i>.sample` (raw, number field "sample #"; `s7`/`s8` knobs dropped); shows "GSM sample N of M in this instrument", GM instrument name/bank/program/regions, or wave. GM library load → GM-instrument source, `sample = 1 + drums·16384 + bank·128 + prog` (per-note regions). GSM samples: library source `gsm` (play decodes via engine, load copies into the instrument, dedup); instrument header "Import sample…" and sampler "Import WAV…" (browser decode → 44.1 kHz mono → `E.gsmEncode`, ≤ 30 s, size + clip report); "▶ Play", "Choose GSM sample…", "Remove unused" (drops unreferenced samples, renumbers slots). Group graphics follow their knobs: `redrawGroup` (rAF-coalesced) from knob change/automation `_set` and selects; `curVal` reads the knob value. `envView`/`envCurve` mirror unisynth env.rs (WaveSabre closed form, Tunefish per-512-block). Sampler: `samplerSettings` named controls (loop Off/Repeat/Ping-pong, region own/custom, interp, reverse), loop knobs only for a custom playing loop, normalised waveform with draggable start/loop edges/body (dragging the own loop makes it custom). Ctrl/Cmd+Z, Shift+Z, Y undo/redo anywhere outside text fields. Tunefish-mode envelope time knobs read `tfEnvSeconds` (attack 0→1, decay 1→sustain with current sustain/slope, release to −100 dB; "holds"/∞ when never ending); env group knob texts refresh with the curve (`_redrawText`). Track name tooltip = `aboutText(t.about)` (type · style · tempo · engine · like … — description). Helpers reached from `fmtVal` (`ip`, `vget`, `INST`, `oscType`, `envMs`) are function declarations: the first `tracks.forEach(buildTrack)` formats automation-lane labels before later `const`s initialise (TDZ "Cannot access … before initialization" on songs automating an envelope time). Engine names after unify-v2-algorithms: envelope `env<i>.law` / `env<i>.curve_slope` (were `mode`/`slope`; a stale name made `ip()` undefined and every song failed to start with "reading 'name'"). `optName(d, name)` reads a choice parameter's option name by stored position (expanded `Law::Kinds` choices put later kinds between the old ones); `oscType` maps it to the kind id (5 Naive, 6 Clocked; `OSC_SHAPES` 5 = mode/colour/ring, 6 = the clocked's nine fields), filter slots are used unless "Off", `envRate(v)` = option "Rate" (the law gained V2's "Frame" at position 1). See change: add-tbl-demo-songs. Store transition (daw-solid-ts 2.3–2.5): `tracks`/`master` are `createMutable` proxies (`ui/state/song.ts`); bulk read-only paths use `raw()` (snap, export, structuredClone, thumbnails, lane draw, `laneValue`, `modeOf`/`tableOf`); `restore` batched → `restoreSong` (reconcile by id; roll clip re-resolved by name/start), history `H` (`ui/state/history.ts`), unsaved = `H.stateId !== savedId` or tempo/sig/bars changed (`markSaved`); `snap()` has no replacer (view fields in `ui/state/view.ts`); `css()` caches the static colour tokens; display state → `liveState` (`ui/state/live.ts`); `DAW.debug.undoDepth()`. Transport (daw-solid-ts 3.3): `mountTransport` runs first in `start()` (header ids exist before any query); app.js keeps `SONG_POS`/`LOOP`/`BARS`/`loopOn`/`followHold`/`recOn` and publishes them to `ui/state/transport.ts` in `updateLoop`/`relayout`/`setRec`/`holdFollow`/`resumeFollow`/`dropsShow`; handlers became functions `onTempo`, `onSig`, `onLength`, `onLoopText` (→ bool), `toggleFollow`, `stopPressed`, `onBuffer`, `onOpenFilters`; `showPos` no longer writes #pos/#time (the bar derives them); playheads `ph`/`ph2`/`#roll-ph` still moved by `showPos` (transform) until the arrangement/roll ports. Files/library (daw-solid-ts 4.2): `mountFiles` + `mountLibrary` right after `mountTransport`; `dlg`/`popMenu`/`renderSongList`/`renderLibrary`/`inspect` gone (ui/common, ui/files, ui/library); handlers became `newSong`, `importFile(file)`, `exportSong`, `bounceSong`; `showErrors` wraps `dialogs.showErrors` (pick → select + focus the track); `CAT` kept for device panels, mirrored by `lib.setCatalog`; `auditionEntry(src, it, done)`; `files.setDirty` in `dirtyUpd` (title + `#saved-info` still written there). Arrangement rows (daw-solid-ts 5.2): `mountTracks` after `lw`; `buildTrack` gone → `mountLane(t, el)` (laneEl + clips) and `mountAuto(t, box)` (automation lanes + '+ lane'), called by mounted rows; `rebuildTracks` bumps `arrange.rev`; `selectTrack`/`updateArmed`/`renderAll`/`knobEdited` publish signals instead of writing header DOM; `renameTrack` → `arrange.setRenamingId`, `renameTo(t, v)` commits; `validateMarks`/`updateCount` gone (reactive). Gotcha: store writes notify at once — a new lane is pushed with its first point (`recordPoint`). Automation target `<select>` builds its option list on first focus/pointerdown/keydown.
