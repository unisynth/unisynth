## ID 38 song-used subset (`crates/glorp`)

Independent `no_std` implementation (independent behavioural implementation from the behaviour below; no original binary or pseudocode included, no song data committed). Standalone API `glorp::id38::Id38` (`new`, `set_param`, `process`), **not** a `synth_core::Device`: that trait's `set_param` cannot report a rejection and would present a partial device as full support.

Behaviour (f32, fixed 44.1 kHz; coefficients recomputed from the parameters, state kept across changes):

- Mode `trunc(P0·11.999)`: 0 low-pass, 1 high-pass (RBJ biquad, DF1 order `b0x + b1x1 + b2x2 − (a1y1 + a2y2)`, coefficients ÷a0). Cutoff `P1²·19980+20` clamped 20..20000 Hz, `w = fc·0.00014247582f`, Q `0.5+29.5·P2²` (α uses `max(Q,0.05)`).
- Output per sample: `(((wet − dry)·P13) + dry)·gain`, `gain = 2·P14` (P14 ≤ .5) else `4·P14 − 1.5`; `wet` = filter output, post-distorted when `trunc(P6·5.999)` is 1 or 2 (distortion is not in the feedback path). `k = P7²·20 + 0.101`, `u = k·x`; type 1: `R(u)/R(k)`, `R(u)=u(378u⁴+17325u²+135135)/(18u⁶+3150u⁴+62370u²+135135)`; type 2: `g(u)/g(k)`, `g(u)=u(u²+27)/(9u²+27)`. The original divides with `rcpps` + one Newton step (CPU-specific); the Rust uses true division.
- Explicitly rejected (`Error`, device unchanged): mode ≥ 2, stages (`trunc(P4·7.999)`) > 0, pre distortion (`trunc(P5·5.999)`) > 0, post type ≥ 3, P12 ≠ 0.5 exactly (envelope amount), any value non-finite or outside [0,1], index ≥ 15. Note events are not part of the API: with a neutral P12 they do not change the output (recorded windows of instances with notes match with none applied).

Verification (this session): synthetic unit tests against an independent f64 model; env-gated `crates/glorp/tests/reference.rs` (`GLORP_REF_ROOT`) replays the 10 active ID 38 instances' recorded 600-block taps (153,600 samples each, inputs/outputs as captured from the Wine-run original, every recorded SetParam accepted): post-distortion-free windows (instances 28, 29, 31, 35, 38; modes LP and HP) bit-exact; windows with post distortion 1/2 (instances 30, 32, 33, 34, 36) max abs error 2.4e-7 (5.96e-8 for type 2). Instance 37 never active: no tap, unchecked. Caveats: same-binary Wine reference, not real Windows; windows are limited to the song's own parameter values; `rcpps` rounding is not reproduced, so distorted output is tolerance-matched, not exact; exact behaviour at mode/type boundary parameter values (e.g. `P0 ≈ 1/11.999`) is untested because the song never sets them.

## ID 34 frequency shifter (`crates/glorp`)

Complete, independent `no_std` implementation (`glorp::id34::Id34`: `new`, `set_param`, `process`, `shift_cycles_per_sample`); behavioural description only, no original binary, table or pseudocode in the repo. Standalone, **not** a `synth_core::Device`, same reason as ID 38.

Windows x64 trace: SetParam `0x14000554a` maps P0/P1/P2/P3 to `this+0x18/0x1c/0x20/0x24` and ignores index > 3; vtable note/slots `+0x10..+0x20` are `ret`; chunk is 4 floats plus a trailing size dword (set via 4 SetParam calls); the ctor defaults P2 = 1.0, P3 = 0.5. Run (`rcx` this, `r8` input pointer pair, `r9` output pointer pair, frame count at `[rsp+0x28]` on entry) reads **only P3** and sample rate never; it computes one phase increment per call and then for each frame calls the shifter with `this+0x28` as state, `r8` = packed `(R<<32)|L`, `xmm3` = increment, and stores `L`, `R` from the returned pair.

Behaviour (f32, scalar SSE order, no FMA):

- Increment: `x = (P3+P3) + -1`, `x8 = ((x²)²)²`, `inc = (P3 < 0.5 ? −x8 : x8) + 1.0`. Net shift is `x8` cycles per sample: P3 < 0.5 shifts **up**, P3 ≥ 0.5 **down** (direction fixed by the tap match, not by labels). Hz = `x8 · fs` (the rate is never read; the song's 44.1 kHz gives 0.8549 → ≈ 2.84 kHz). P3 = 0.5 is zero shift.
- Phase: `v = inc + φ`, `φ = (1 < v) ? v + (−1) : v`, updated before the sine is read. At most one subtraction, so a downward shift (`inc > 1`) increases `φ` without bound (≈ 6e4 at the first song tap) and the f32 phase resolution decays to 1/256 cycle there; an upward shift stays in [0, 1]. Reproduced as is, so a replay must run from block 0.
- Two chains of four all-pass sections `y = c·x + (−1)·x₂ − (−f)·y₂` (`x₂`, `y₂` two samples back; states are stereo pairs). Chain A takes the input, chain B the input delayed one sample (`this+0x28` holds that sample). `c`: A 0.161758, 0.733029, 0.94535, 0.990598; B 0.479401, 0.876218, 0.976599, 0.9975 (6-digit squares of Niemitalo's published polyphase coefficients). `f = c` everywhere except chain A section 1, where the original feeds back 0.1617158.
- Output per channel `cos(2πφ)·A + sin(2πφ)·B`: `θ = φ·6.2831855`, sine from a 513-entry table `sinf(i · 0.012271847)` (the original fills it at start-up), read via `t = θ·0.15915494`, `frac = (t + 1) − floor(t)` (floor by truncation plus one correction), top 9 mantissa bits of `frac` index, low 14 bits interpolate: `(b − a)·w + a`; cosine = sine of `θ + 1.5707964`.

Verification: synthetic unit tests against an independent f64 model, single-sideband spectral tests (sideband at `f0 ± shift`, image ≥ 30 dB down) and the env-gated `crates/glorp/tests/reference34.rs` over the two active instances (song devices 25, 26; 153,600 samples each): device 25 bit-exact, device 26 max abs error 1.19e-7 (1 ulp, 361 samples). The only known deviation is table node 305, where Rust `libm::sinf` is one ulp from the original's msvcrt `sinf`; patching that node in a scratch run made both instances bit-exact (not kept: the table stays libm-derived). Caveats: same-binary Wine reference, not real Windows; only the tapped windows' P3 values are covered (device 25: automation sweeping 0.854 → 0.447, so both shift directions and the centre crossing; device 26: constant 0.2667; device 25's P3 later reaches 0.00015 outside any tap), other values rely on the f64 model and the structural trace; the replay window follows silence, so a nonzero-from-start input is covered only by the model tests; behaviour after ~2²⁰ downward-shifted samples follows from the same arithmetic but is unchecked against the original; no note/time handling because the original has none.

## ID 35 all-pass cascade (`crates/glorp`)

Song-used subset, independent `no_std` implementation (`glorp::id35::Id35`: `new`, `set_param`, `process`); behavioural description only, no original binary, table or pseudocode in the repo. Standalone, **not** a `synth_core::Device` (same reason as ID 38/34). Settings outside the subset return `Error` and leave the device unchanged.

Windows x64 trace: SetParam `0x140004cae` maps P0..P5 to `this+0x18/0x1c/0x20/0x24/0x28/0x2c`; index > 5 is ignored by the original (rejected by the Rust API). Vtable slots 2..4 (note on/off, …) are `ret`; slots 5/6 only store the global sample rate / block size; chunk load is a SetParam loop. There is **no reset entry point**: stage state is zeroed once by the constructor (`0x140004616`) and never again, not on parameter, stage-count or topology changes. Constructor defaults P0..P5 = 0.286, 0.885, 1.0, 0.974, 1.0, 1.0. Run reads all six parameters at the start of every call (block granularity, no per-sample smoothing), re-derives the coefficients, runs the cascade and writes `out = (wet − dry)·P2 + dry` per channel. Input and output are separate pointer pairs in the ABI; the harness calls the original with the **same buffers for both** (in place) and the song tap replays bit-exactly, and the original never touches the aux pair (asserted per block by `reference35.rs`). The Rust `process` is in place (an input sample is read before its output is written).

Behaviour (f32, scalar SSE order, no FMA, fixed 44.1 kHz: `2π/44100` is baked into the stage coefficients and the rate is never read):

- Stage count `n = trunc(P3·256)` ∈ 0..=256; topology `trunc(P5·2.999)`: 0 delay-line Schroeder all-pass (uses `P1` as feedback `1.98·P1 − 0.99`), 1 first-order, **2 second-order (the only one implemented; P5 ≥ 2/2.999 = 0.66689)**. Topologies 0 and 1 are read from the assembly only, never tap-checked, and are rejected (`Error::Topology`).
- Stage `i` frequency: 32-bit integer finaliser of `i·1234567` (`h ^= h>>16; h *= 0x7feb352d; h ^= h>>15; h *= 0x846ca68b; h ^= h>>16`) mapped to `u = h·2⁻³¹ − 1 ∈ [−1, 1)`; `f = 2^(u·3·P4) · (P0²·19980 + 20)` clamped to 20..20000 Hz. `w = f·0.00014247585`.
- Q = `max(0.5 + 19.5·P1², 0.5)`, `α = (sin w · 0.5)·(1/Q)`, `inv = 1/(1+α)`, `c1 = (cos w · −2)·inv`, `c2 = (1−α)·inv`.
- Per sample and channel (L/R lanes independent), stage by stage, with `u`, `v` the stage's two previous internal values: `w = x − ((c2·v) + (c1·u))`, `y = ((c1·u) + v) + c2·w`, then `v ← u`, `u ← w`; `y` feeds the next stage. States of stages above the live count are **kept** and resume from their old values when the count rises again (unit- and Wine-vector-tested: `vec05` jumps 200 → 20 → 240 → 0 → 128). Flush-to-zero/denormals-are-zero are on in the original and in `process`; a ring-out ends in a sub-1e-37 rounding limit cycle, not exact zero.
- Coefficients depend only on the parameters, so the Rust device re-derives them lazily when a parameter changed.

Song instance: device 27 (channel 9: 7 (ID22) → 25 (ID34) → **27 (ID35)** → 31 (ID38)), chunk P = 0.1557, 0.9246, 0.992, 0.9978, 0.455, 1.0; automation lanes P0..P4 (41, 24, 36, 3, 4 points), never P5. Recorded writes over the song: P0 0..0.570, P1 0..1, P2 0.239..1, P3 constant 254/255 (254 stages from block 0 on), P4 0.455..1, P5 constant 1.0 (second-order).

**Exact boundaries.** Supported: every value in `[0, 1]` of P0..P4 and any P5 with `trunc(P5·2.999) = 2`. Rejected, atomically (`Err`, device unchanged, also in `new`): index ≥ 6, non-finite or outside [0, 1], topology 0 or 1. Unsupported/unverified: topologies 0 and 1; the delay-line topology's other parameter reads; any sample rate other than 44.1 kHz (the original has none); aux pair (untouched, outside the API); note events (the original does nothing with them).

Verification (isolated Wine harness; all against the same-binary Wine reference, not real Windows). Harness additions (outside git, `analysis/harness/README.md`): `GLORP_OUT_TAP` (replay writes the original's output as a tap, so synthetic inputs can be measured), `GLORP_DUMP_COEF` (per-block original coefficient arrays), `fnprobe` (the linked C library's `sinf`/`cosf`/`powf` on 2 M points).

Independent `no_std` implementation (`glorp::id32::Id32`: `new`, `set_param`, `process`); behavioural description only, no original binary, table or pseudocode in the repo. Standalone, **not** a `synth_core::Device` (same reason as ID 38/34/35). `process` returns `Result` (see Delay below), unlike its siblings.

Windows x64 trace: ctor `0x140009ecc` (`this+0x18..0x40` = P0..P10 as floats, defaults P = 0.2, 0.5, 0.3, 0.5, 0.5, 0.3, 0.5, 0, 0.5, 0, 1.0; unused by the Rust API, `new` takes all 11) allocates **16** stereo delay lines of **2205** samples (`0x89d`, helper ctor `0x140004d50`), `this+0xc8..0x108` = 16 LFO phases, `this+0x108` the smoothed base delay, `this+0x10c` a stereo pair (mode B feedback), all zero. Note slots `+0x10..+0x20` are `ret` (`0x140009870`); no reset anywhere; sample rate is never read (the `44100` baked into the line helpers is a constant). Behaviour (f32, scalar SSE order, no FMA):

- **Enable** `P10 < 0.5`: Run returns immediately; the output buffer is not written, all state frozen. The harness calls the original in place, so the block passes through (`vec08`); the song never disables a device (P10 = 1 everywhere) and whether the engine ever passes distinct input/output buffers to this device is not established. Mode `P7 < 0.5` A, `≥ 0.5` B (per sample, but P7 is constant inside a block).
- **Line** (`0x30` bytes + ring): read position `widx − cur·44100` (+ ring wrap, at most twice), linear interpolation `frac·b[i1] + (1−frac)·b[i0]`; push: `cur ← (target − cur)·min(coef+0.001, 1) + cur` (the coefficient is the constructor's 1.0 ⇒ full step, `cur` is still `(t−c)+c` in f32), then `widx ← widx+1 < 2205 ? widx+1 : 0`, `buf[widx] ← v`. Every call reads with the `cur` left by the previous push.
- **Base delay** `target = 0.4·P2³ + 0.002` s; `dsm ← (target − dsm)·0.001 + dsm` every sample (f32, starts at 0, stalls ~500 ulp short of the target).
- **Mode A**: `n = min(2·trunc(12·P0)+2, 16)` lines (2, 4, …, 16; P0 ≥ 7/12 ⇒ 16). Per line `i`: `m = sin(i)·P9 + 1`; delay `P4³·(0.8·dsm)·sin(i·π/n + φᵢ) + dsm` s (to `line.target`); `tap = read`; `push(tap·fb + in)` with `fb = 2·P3 − 1` (signed); `φᵢ ← wrap₂π(m·rate + φᵢ)`, `rate = P5²·15040·P5/44100` (one subtraction of 2π when ≥ 2π); accumulate `tap·w` with `w = (1+P6, 1−P6)` for even `i`, swapped for odd `i`. Output `(P1·(2.25/n))·acc + (1−P1)·in`.
- **Mode B**: `x = in + fb·pair`; `n = min(trunc(10.999·P8)+2, 16)` (2..12) sections in series; section `i`: delay `max((sin(i·π/n + φᵢ)·P4 + 1)·(0.005·P2³ + 0.0001), 1/22050)` s, `tap = read`, `w = x − g·tap`, `y = g·w + tap`, `push(w)`, `x ← y`, `g = min(P3, 0.999)`; `φᵢ ← wrap₂π((i·0.3/n + 1)·rate + φᵢ)`. `pair ← x`, output `P1·x + (1−P1)·in`. Section delays are ≤ 0.0102 s = 450 samples ⇒ always inside the line.
- Lines above the live count (and their phases) are not touched: they freeze and resume with their old history (vec04, vec07, vec08 cover it).

**Delay (rejected).** In mode A the read distance can reach `dsm·(1 + 0.8·P4³)·44100` samples; the original reads before the start of its 2205-sample line past two ring wraps (undefined, not reproduced). Rust: `Error::Delay` when the worst case exceeds `MAX_DELAY_SAMPLES = 2200` — in `new`/`set_param` for the target, and in `process` for the current glide state (`max(dsm, target)`; the glide is monotone), refusing the block without touching buffers or state. Unsupported: sample rates ≠ 44.1 kHz; note events; the original's separate input/output pointers (the API is in place: a disabled device cannot copy input to a distinct output); values outside [0, 1] (the original does not clamp; behaviour not characterised); delay beyond the line.

SetParam stores: P0 `+0x1c`, P1 `+0x20`, P2 `+0x24`, P3 `+0x28`, **P4 `+0x18` = `trunc(u·3.999)`**, **P5 `+0x40` = `trunc(2u)`**, P6 `+0x2c`, P7 `+0x30`, P8 `+0x34`, P9 `+0x38`, P10 `+0x3c` (everything else raw). The only library call is `powf` in the knee. The decompiler's pseudo-C is wrong on one point that the assembly settles: in mode 3 the sign is `seta; sbb 0` after `ucomiss`, so a **NaN counts as −1**, not 0.

Behaviour (f32, scalar SSE order, no FMA; parameters re-read once per Run call; the left block is processed entirely before the right one):

| param | law (u = value) |
|---|---|
| P0 drive `k` | `u < 0.2` (strict, `0.2 > u`): `u + 0.8`, else `5·(5u − 1)² + 1` |
| P1 ceiling `c` | shaper input `x·k / c`, shaper output `clamp·c` (`0` is IEEE: ±inf/NaN into the clamp times 0) |
| P2 fold `f` | mode 0 only, when `f > 0`: `y < −1` (or NaN) → `f·(−1 − y) − 1`; `y > 1` → `f·(1 − y) + 1` |
| P3 mix | `out = x + (wet − x)·u` (**not** protected against inf: `inf − inf = NaN`, also for mix 0) |
| P4 mode | 0: fold above; 1: `y·1.570796` (f32 `0x3fc90fd8`); 2: `y·(y·y)`; 3: soft knee below. Then clamp to `[−1, 1]` (NaN → −1) times `c` |
| P5 averaging | `trunc(2u)`: 0 none; 1 (`0.5 ≤ u < 1`) 2-point; 2 (`u = 1`) 4-point |
| P6, P7 gains | `u > 0.5`: `4u − 1.5`, else `2u` (input gain on the direct path before the shaper, output gain after it) |
| P8, P9, P10 | mode 3: threshold, width `w`, slope. `a = |y|` (sign `s`, 0 for ±0, −1 for NaN), `t = a − thr`; `2t < −w` or NaN: `a`; `2t > w`: `t·slope + thr`; else `a + (t + w/2)²·(slope − 1)/(2w)` (`powf(·, 2)`); result `a·s` |

Averaging, with `x` the input and `prev` the previous raw input of the same channel: `d = S(x·g_in)·g_out`; 2x: `wet = (S((prev + x)/2) + d)/2`; 4x with `m = (prev + x)/2`: `wet = (((d + S(m)) + S((prev + m)/2)) + S((m + x)/2))·0.25`. **The sub-sample paths get neither the input gain nor the output gain** (so with unequal gains the averaged output is a mix of differently scaled paths: observed in the assembly and by the vectors, `vec06` fails if gains are applied there); the drive `k` is applied everywhere. `prev ← x` (raw input), no other state, no reset. The aux pair is neither read nor written; output = input buffers in place.

**Exact boundaries.** Supported: every value in `[0, 1]` of all 11 parameters (incl. ceiling 0 and width 0, which are IEEE-exact, and the mode / averaging quarter and half boundaries), any input including NaN / infinity (an infinite input gives NaN, a NaN input gives NaN for that sample only because the shaper clamps NaN to −1), zero-length blocks. Rejected: index ≥ 11, non-finite or outside `[0, 1]` (the original accepts anything, not characterised; e.g. P4 > 1 would select a mode beyond 3). Unsupported / out of scope: note events (inert), the aux pair, the original's separate in/out pointers (in place only), any `Device`/`Kinds` integration. Nothing in the parameter space is approximated. Sample-rate independent: Run reads no rate.

## ID 25 percussion synth + shared 16-voice scheduler (`crates/glorp`)

Independent `no_std` implementation (`glorp::id25::Id25`: `new`, `set_param`, `note_on`, `note_off`, `process`; scheduler in `glorp::synth`); behavioural description only, no original binary, table or pseudocode in the repo. Standalone, **not** a `synth_core::Device` (same reason as the other Glorp devices). One instance in the song (song device 8, channel 7, 64-byte chunk = 15 params + the size float; chunk float 0 is P0: an earlier listing that started at 0.573 was misaligned by one float). 256 events (128 note-on + 128 note-off), low notes such as 23, 18, 2, 59, 44; **pitch-independent**: the note number only seeds the filter randomisation (velocity is ignored, never read). Windows x64 trace: ctor `0x14000bfc4`/`0x14000c05c` (vtable `0x14001ad70`), NoteOn `0x14000c0e0`, voice Run `0x14000ca24`, shared synth Run `0x14000f46e`, ADSR tick `0x140003b82`, biquad init `0x1400040a4` (types 0..8, RBJ), biquad tick `0x140003d82`, sine `0x140004517`.

**Shared scheduler** (poly mode, one voice per note; mono/legato slide, unison and voices-per-note ≠ 1 exist in the original but no song chunk uses them: not modelled). 256-slot queue of `{kind, delay, note}` (the shared device at `+0x34c`, entries of 16 bytes); an event takes the **first free slot**; a full queue drops it (`Error::QueueFull` here). Run zeroes both outputs, then loops: scan slots **in slot order**, an event with `delay > 0` only shortens the sub-block, one with `delay == 0` fires and frees its slot (note-on: **lowest-index inactive voice**, none free ⇒ the note is lost, no stealing; note-off: releases **every** active voice playing that note); then all active voices render the sub-block in index order (float accumulation order matters), delays shrink. A voice stays active until its own envelope reaches 0 and still renders the rest of the sub-block it ended in. Consequences pinned by `tests_synth.rs` and the vectors: same-offset events fire in slot order, but an event queued after a slot was freed takes the lowest free slot and can **overtake** an older event with equal remaining delay; offsets beyond a block stay queued across calls.

**Voice** (per note; params P0..P14 are re-read every sample, so automation acts on sounding notes; note-on draws the filter randomisation from P14 as it is at that moment): ADSR `A 0.001, D 0.5, S 0, R 0.5` s (sustain 0 never decays below it: the voice lives until note-off, then the release stage ends it; note-off while a note rings releases it), body = sine with exponential pitch sweep (P0 base frequency, P3/P10 sweep, P2 decay) phase-modulated by lowpassed hashed stereo noise (P7, P11/P12 modulation decay/depth, P5 noise decay) plus a detuned sine layer (about 691.15 / 694.29 rad/s terms, P6 mix, P13 decay), 3 + 2 cascaded biquads (shelves, peaking), mix, gain P9 · 0.4, piecewise soft limiter (knee 0.6..1.4, correction `−0.5625·u²`), per-sample ADSR, accumulated ×3. 7 live biquads per voice (the 8th at voice offset `0x244` is configured but never run). Note-on PRNG: chained `lowbias32` (`0x7feb352d`, `0x846ca68b`, `0x9c2d0d6f`) seeded from `note·0x12d687 + 0x765fbdc`, ×2⁻³² to floats, draws h4.. in sequence; P14 = 0 turns randomisation off. P1, P4, P8 are stored but **not read** (accepted, ignored; negative-controlled as inert). Sine = the `id34` 512-node table (node 305 patched +1 ulp, as for ID 32/34). Fixed 44.1 kHz; FTZ/DAZ like the reference.

**C library arithmetic and exponential provenance.** The original's `expf` and `powf(2, e)` are Wine's msvcrt, which is neither `libm`'s nor correctly rounded (probed on 2,000,000 random f32 inputs with a standalone program run under the isolated Wine, outside git: `expprobe.c` only calls the library and records `{x, expf, sinf, cosf, powf(2,x)}`). An earlier revision of `id25.rs` reproduced those two functions bit for bit (0 mismatches of 2 M) with a 32-entry `2^(i/32)` f64 table, three polynomial coefficients and a `SHIFT` / `ki % 32` / `ki << 47` / Horner evaluation. **That scheme was removed because its provenance cannot be documented as independent.** What the records show: the table is plain mathematics (`2^(i/32)` correctly rounded, any IEEE implementation derives the same bits); the three coefficients are **not** Taylor terms (c0 = 0.0555036 vs ln³2/6 = 0.0555041) but a specific minimax set whose 52-bit values cannot come out of an unrecorded fit by chance, and the evaluation structure is the published musl / ARM optimized-routines `expf` (the code Wine's msvcrt carries; upstream MIT / Apache-2.0, Wine LGPL). The session log of 2026-10-27 only says the scheme was "found" by probing 2 M outputs; no fitting script, derivation, disassembly or source reference was kept (`expprobe.c` is the only artefact), and the coefficients were not checked against a local copy of that source (none on disk). So independent derivation is **not evidenced**; the helper is treated as derived from that source and replaced. `crates/glorp` never committed it (the crate is untracked). Current code: `expf(x)` = f64 `libm::exp` rounded once to f32, `2^e` = f64 `libm::exp2` rounded to f32. `sinf`/`cosf` are f64 `libm::sin/cos` rounded to f32 (0.14 % of arguments 1 ulp off the original); an earlier attempt to transcribe the original's sine routine mismatched 1,236 of 664,347 probes and was **not** used (and is not relied on here). Limiter knee `powf(u, 2)` is `u·u` (original 1 ulp high on 0.07 % of 3 M probes).

## ID 27 comb-resonator percussion synth (`crates/glorp`)

Independent `no_std` implementation (`glorp::id27::Id27`: `new`, `set_param`, `note_on`, `note_off`, `process`, `active_voices`, `voice_notes`; scheduler in `glorp::synth`, shared with ID 25 unchanged); behavioural description only, no original binary, table or pseudocode in the repo. Standalone, **not** a `synth_core::Device` (same reason as the other Glorp devices). Two song instances (56-byte chunk = 13 params + the size float): **device 9** (channel 13, chain 9 → ID 30 → ID 34, 41 note-ons of note 16) and **device 10** (channel 12, chain 10 → ID 30 → ID 38, 300 note-ons of notes 2/12/63/68/71, up to 16 simultaneous voices; an offline estimate from the event log says about 72 note-ons are lost to voice exhaustion). **No parameter of either instance is automated** (the song file has automation lanes only for IDs 30/34/38, and the whole-song event log holds no `SetParam` row for devices 9/10), so "automation" coverage comes from the synthetic vectors (`vec09`: mid-note writes of every parameter class). Windows x64 trace: device ctor `0x14000b000` (defaults `.1 .86 .534 .034 .252 .336 .725 .5 .045 .286 .252 .336 .725`), voice ctor `0x14000b088`, NoteOn `0x14000b152`, voice Run `0x14000b5f4`, shared synth Run `0x14000f46e`, delay helpers `0x140004d50/e92/e44/f22`, RBJ `0x1400040a4`, biquad tick `0x140003d82`, table sine `0x140004517`; disassembly in `analysis/id27-impl/` (external).

**What a voice is** (full formulas in the `id27.rs` module doc). A fixed one-shot: the f32 clock `t += 1/44100` per sample, freed by the sample that makes `t > 2.5` (it still renders that sample). **f32 accumulation makes that 110,349 samples (2.5022 s), not 110,250**; ADSR and note-off do nothing audible (the ticked ADSR output is discarded; NoteOff only rewrites the ADSR), so a voice is never released and a note-off only occupies a queue slot. The note only seeds a hash chain (`seed = note·1000 + 412412`, the same `lowbias32`-style mixer as ID 25); velocity does not exist. NoteOn draws seven values (the 4th and 5th are consumed and unused): tone `f = max(|400·P2 − 350 + 200·u₁³|, 50)` Hz (both combs delay `0.5/f` s), loop-filter bases `hp0 = 20 + 0.3f + 200u₂ − 2000P4`, `lp0 = 220 + 0.3f + 200u₂ + 1200u₃² + 2000P5`, a smoothstep `s` of `u₆⁴` that sets the short comb (`1/(2050 + 20000s)` s, 2..21 samples) and its low-pass (`20 + 20000·u₇·(P11² + s)`), its high-pass `20 + 20000·P10²`, a fixed 8 kHz Q 0.36 hiss low-pass. Per sample: noise pair `(nA, nB)` (R, L) + a 100 Hz saturating "square" `sq = sgn(s)(1 − e^{−k|s|})/(1 − e^{−k})` (`s` = table sine, `k` 110.9 or 115.336) form a 5 ms burst `(n + sq)e^{−200t}`; comb A `delayA ← exc − g·HP(LP(r0))` (negative feedback), comb B `delayB ← exc + g·HP(LP(r1))`, `g = 0.85 + 0.14·P3`; the four loop biquads are **re-designed every sample** (low-pass corner `lp0 + 2000·P9·e^{−20t}`, high-pass `hp0`, Q 0.7); `m = exc + P0·r0 + P1·b`; the short comb `h = HP(LP(m + 0.99·c))`; `o = (1 − P12)m + 0.5·P12·h`; saturator `y = tanh(drv·o)/tanh(drv) + 0.2e^{−20t}·tanh(10·hiss)` with `drv = 10P7 + 0.001` and **tanh = the [7/6] Padé** `x(378x⁴+17325x²+135135)/(18x⁶+3150x⁴+62370x²+135135)` (not the real tanh); `out += P8·y`. P6 is never read (sweeps `s06lo` = `s06hi` = baseline bit for bit in the original); P2/P4/P5/P10/P11 are read at note-on only. This corrects the earlier lead: P3 is the feedback gain (read), P7 is the drive, P12 the short comb's wet mix, P9 a cutoff sweep, P10/P11 short-comb filters.

**Delay lines** (the part that is easy to get wrong): 44100-entry stereo lines, read at the f32 position `(time)·(−44100) + w`, wrapped into `[0, 44100)`, linear interpolation; the write updates `time ← (target − time)·1 + time` (smoothing gain 1.0 set at note-on) then advances `w`. NoteOn clears the **contents** but **not `w` and `time`, which persist between the notes of a voice** (a never-used voice starts at 0). The f32 position has a resolution of 0.004 sample near 44100, so the fractional delay depends on `w`, and the rounding of `(target − time) + time` depends on the previous note's tone. Only lags up to 442 samples are ever read, so the Rust keeps 512-sample rings plus the 44100-modulus bookkeeping (≈ 200 KB for the 16 voices instead of 17 MB). Experiment (diagnostic build, not kept): resetting `w`/`time` at every note-on raises `vec13` (sequential notes on one voice) from 6.0e-4 to 1.22e-2 of peak and drops device 9 from 85.1 % to 74.9 % exact samples: the persistence is real and matters.

Velocity does not exist.

**Map** (`0x14000715e`): the frame is computed at run time from `sqrtf(2.48)` and three constants (`u ∝ (−1, −1.2, 0.2)`, `n ∝ u × (0, 1, 0)`, `v = n × u`; a proper rotation of 169.74°); per iteration rotate, coupled sine step `x += sin z, y += sin x, z += sin y` (of the rotated point, simultaneous), trig vector of the new point (`sin` / `cos = tsin(· + 1.5707964)`), accumulate with decay `1/a` (`A ← (A ± …)·(1/a)`, `W ← (W + 1)·(1/a)`), then the point times `b`; result `(A0, A1, C)/W`, i.e. `Σ aᵏ·dₖ / Σ aᵏ`, `|out| ≤ 2`. For `b > 1` it is chaotic: the f32 operation order of the instruction-emulated closed form (500/500 bit-exact against the emulator) is kept, and **every non-exp rounding is IEEE-exact** (`sqrtf`, `+ − × /`, `cvttss2si`, the table sine incl. its out-of-range behaviour), so only `2^x` (via `ω`) and the ADSR's `exp` come from `libm` (f64 result rounded to f32).

**Finite-domain singularities** (found on the original with synthetic vectors, `unsafe_*`, captured in the container):
* `W` is accumulated as `W ← (W + 1)/a`, so `a = 0.002` (P2 = 0) gives `500ⁿ`: **n = 15, 16 return NaN** for the whole note (`unsafe_n15`: 11,358 NaN samples, `unsafe_n16`: 11,360), n ≤ 14 is finite (`vec19`: 500¹⁴, peak 1.06, matched). P2 = 2e-4 with n = 16 (W ≈ 2.4e38, just below `f32::MAX`) returns NaN on 32 samples and 0 elsewhere (the numerators overflow before `W` does), P2 = 1e-3 with n = 16 is fine (`vec23`, 83¹⁶, matched).
* `n ≤ 0` (unreachable from a parameter in `[0, 1]`) is NaN too (`0 · ∞`); P4 < 0 would be that.
* Large arguments are not a hazard: the table sine returns a finite value for any f32, including NaN and ±∞, and `φ`, the z ramp and `b¹⁶` stay far below the f32 range for any realistic note length (6 s at note 127 tested).
* Rust guard `id22::check`: `Error::Range` outside `[0, 1]`, **`Error::Weights` when `W(10·P2 + 0.002, trunc(15·P4)+1) > f32::MAX / 4`**, accumulated in f32 exactly as the voice does (the factor 4 covers `|A| ≤ 2W` with rounding and keeps the reciprocal finite; it refuses n = 15 at P2 = 0, P2 = 2e-4 / n = 16, accepts n = 14 at P2 = 0 and P2 = 1e-3 / n = 16). Monotone in P2 (falling) and P4 (rising). `set_param` judges the **whole resulting vector** (order hazard: lower P4 before P2, raise P2 before P4). The song preflight judges a lane box on the corner (lowest P2, highest P4, widened by `MARGIN`): a pair of lanes that are each fine alone but not together is refused (`Reason::Automation`), as is a lane that only touches the corner in the middle; a `Device` driven by hand latches `Fault` and renders silence instead of NaN.

## ID 20 negative-feedback comb resonator (`crates/glorp/src/id20.rs`, measured 2026-10-30)

Independent `no_std` implementation (`glorp::id20::Id20`: `new`, `set_param`, `note_on(note, velocity, offset)`, `note_off`, `process`, `active_voices`, `voice_notes`, `check`; the shared scheduler in `glorp::synth` gained per-event velocity, `note_on_vel` / `Voice::start_vel`, with `start` unchanged for the other instruments). Behavioural description only, no original binary, table or pseudocode in the repo (module doc has the formulas). Analysis outside git: `analysis/id20-impl/`; the original ran only in the isolated `--network none` Wine container, new files only under `harness/out/id20impl/`.

**What it is.** 16 voices, 16 parameters **latched at note-on** (the render loop reads none), poly only. A note seeds a hash chain (`note + trunc(150·P0) + 0x765fbb8`, `lowbias32`); the 68 draws of the note-on set 16 comb lines in 4 groups of 4 (tone `500 + 14500·P(1+g)²` Hz ± `P7` jitter, negative feedback `0.5 + 0.49·P5 .. 0.999` blended by `P6`, loop high/low-pass from `P8`), a per-group frequency-shift increment from `P9` and a master shift `4000·P15 − 2000` Hz. **Only groups 0..2 (12 lines) are rendered: the fourth group, and so `P4`, is inaudible.** Excitation = high/low-passed noise (`P10`, `P11`) times an envelope `e^((P13 + 0.1·v)/735 − 1/630)` per sample plus a decaying click sine (`P12`, `P14`), scaled by velocity `v = vel/128`. Output = the raw delay taps summed per group through the ID 34 Hilbert shifter, halved, shifted again by the master shifter. Delay lines (contents, smoothed time, write index), shifter state and phase, the noise filters and the level follower **survive from note to note of a voice**. NoteOff does nothing. **A voice ends when its level follower falls below 1e-4, checked at the end of every sub-block**, and the follower starts at 0 and is never reset: a note whose first sub-block is a few samples long (another event right after it, or the block's last samples) is freed before it is heard (`kill_a`: offset 127 silent, 126 heard). The follower's rise gain is 0.101, not 0.001 (a 0.1 term from the constructor's parameter block plus the base 0.001; found because a 0.001 follower freed young voices the original keeps, `kill_b3`).

**Velocity ceiling.** The noise envelope's per-sample factor exceeds one from velocity 214 with P13 = 1: the original's noise then grows without bound (the `unsafe_v214` tap does not decay and the `unsafe_v255` tap's late output is > 1000× its early output). `id20::MAX_VELOCITY` = 213 is the largest velocity whose factor stays below one for every P13; `Id20::note_on` refuses a higher one (`Error::Velocity`), the song preflight refuses a track that carries an ID 20 and plays a note-on above it (the song format carries 0..=255; the refusal names the device), and a hand-written `note_on` above it latches the device fault.

## Isolated reference harness
