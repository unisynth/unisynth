- `Id35::new(&[f32;6])`, `set_param(i, v)` (atomic: `Err(Index)` i ≥ 6, `Err(Range)` non-finite / outside [0,1], `Err(Topology)` when `trunc(P5·2.999) != 2`), `process(l, r)` in place (equal lengths, panics otherwise; aux pair out of scope).
- Up to 256 second-order RBJ all-pass stages (`trunc(P3·256)`), stage `i` at `2^(hash(i)·3·P4)·(P0²·19980+20)` Hz (20..20000), Q `0.5+19.5·P1²`, DF-II (`w = x − (c2·v + c1·u)`, `y = (c1·u + v) + c2·w`), mix `(wet−dry)·P2+dry`.
- Coefficients re-derived lazily (pure function of params).
- **No reset anywhere**: stage state is kept across param / stage-count changes (stages above the count keep history).
- Fixed 44.1 kHz.
- `2^e`, `sin`, `cos` are f64 results rounded to f32 (the original's C library is not `libm`'s: see research doc).
- `scatter` rounds the u32 hash to f32 exactly as the reference (the f64 test model uses the exact hash).
- Output is tolerance-matched, not bit-exact, bounds depend on the `libm` version locked in `Cargo.lock` (0.2.16 when measured; re-measure after a bump, no exact pin): song window max 3.170e-3 (peak 3.4), 6 of 8 synthetic Wine vectors bit-exact, automation vectors 1.5e-5 / 2.0e-4.
- Topologies 0 (delay-line) and 1 (first-order) rejected, unverified.
- External math experiment (not in repo, provenance unclear, no change recommended alone): a candidate `2^e`/`sin`/`cos` makes dev 27 bit-exact on the original input, but the full song only moves 60.397 % / 136 → 61.298 % / 152; 83.469 % / 10 needs the original's dev 27 input (hypothetical oracle).
